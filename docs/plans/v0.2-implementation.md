# v0.2 Implementation Plan

Status: planning baseline, 2026-08-25 · Owner: Hung Vo · Scope source: [v0.2.md](v0.2.md)

This decomposes the v0.2 release plan into an execution sequence of vertical slices.
Each slice ends committed and verified (per [`../progress.md`](../progress.md) convention)
and leaves the CLI in a working end-to-end state: ingest → analyze → report. Horizontal
layers are avoided so every merged slice has standalone value or retires a release risk.

## Strategy Decisions

1. **QML parsing:** `tree-sitter-qmljs` is the primary parser, evaluated early (S2)
   against the documented kill criterion (<99% entry-point / <95% all-QML coverage).
   Failure demotes AST-dependent conclusions to lexical spans; it does not block the
   release. Decision recorded as an ADR plus report metadata.
2. **Sequencing:** vertical slices S0–S8 below, not the horizontal M1→M9 order.
   Traceability to the release milestones is listed per slice.
3. **Dates:** none preassigned. Slice sizes are coarse effort signals; calendar dates are
   set from measured delivery throughput, consistent with [README.md](README.md).
4. **Report compatibility:** the analyzer emits through the existing
   `omasafe.report.v1` envelope using additive optional fields (`analysis` object:
   policy identity, fingerprint, payload inventory, capabilities, findings, evidence,
   coverage). Inventory/trust outputs stay byte-compatible. A breaking envelope bump is
   not planned within v0.x.
5. **Crate layout:** one new crate `omasafe-analyzer` (ingestion, payload inventory,
   parsers, rule catalog, fingerprints). No crates for v0.3+ subsystems. Rule data lives
   in a versioned static catalog inside the crate, not embedded fixture blobs.

## Target Repository Shape After v0.2

```text
crates/

```

## New CLI Surface (regenerate assets via scripts/generate-cli-assets.sh)

```text
plugins analyze PLUGIN_ID       [--format text|json] [--policy PATH] [--fail-on SEVERITY]
scan-plugin (--path DIR | --git URL --revision COMMIT) [--format text|json] [--fail-on SEVERITY]
rules list                      [--format text|json]
rules explain RULE_ID           [--format text|json]
plugins review PLUGIN_ID        --action suppress|reinstate --rule RULE_ID [--path SCOPE]
                                --reason TEXT --yes                      # added in S5
plugins review-update PLUGIN_ID --expected-commit SHA [--yes]            # --yes requires --expected-commit
scan                            [--include-analysis]                     # added in S5, off by default
```

Argv-only dispatch stays hand-rolled as in v0.1; no new argument-parsing dependency.
Each landing slice extends `scripts/generate-cli-assets.sh` (man page and completions
are hand-maintained there, and the consistency test compares top-level names only),
not just `docs/cli-surface.txt` rows.

## Slices

### S0 — Analysis foundations and security-surface reverify · Size M · maps to M1, part of M4

- Reverify [`../reference/omarchy-security-surface.md`](../reference/omarchy-security-surface.md)
  against the current supported Omarchy/Quickshell versions; record the verified version
  range and refresh reachable sinks where the release moved.
- Create `omasafe-analyzer` with: stable rule-ID registry, severity table with its own
  version, capability definitions derived from the surface doc, and configured limits
  (time/files/bytes/depth/evidence caps). Extract these from the private v0.1 constants
  in `omasafe-plugin-trust` into a shared bounded-ingest module — the existing walker has
  no depth or elapsed-time budget and Git calls use blocking `Command::output()` without
  timeouts or cache/disk quotas, so analyzer ingestion needs this generalization to meet
  the frozen untrusted-input contract rather than overstated reuse.
- Define `PolicyIdentity` (analyzer/rule-catalog version, parser versions, limits hash,
  severity-table version, equivalence-map version, supported-surface version) and the
  `AnalysisFingerprint` canonicalization (sorted normalized results; excludes timestamps,
  prose, excerpts, temp paths, tool version) as pure types with property tests.
- Extend `omasafe-report` with the optional `analysis` object schema (documented,
  additive); wire nothing into the CLI yet beyond `rules list`.
- Exit: `omasafe-cli rules list` renders the seeded catalog; policy identity is
  deterministic across builds; surface doc carries a fresh verification stamp.

### S1 — Payload inventory end-to-end · Size L · maps to M2 (edges land in S3)

- Ingestion frontends over one shared walker: installed plugin tree (primary), local
  directory (`scan-plugin --path`), and immutable Git revisions (`scan-plugin --git`,
  reusing the v0.1 commit-pinned fetch machinery — no hooks/submodules/LFS/checkout
  filters, argv-only Git, bounded cache writes).
- Classify and inventory every relevant file: QML, JavaScript, shell, Python,
  extensionless executable, ELF/PE/Mach-O indicators, other binary, unsupported — each
  with mode, size, SHA-256 digest, and explicit coverage state
  (`analyzed|partial|skipped|truncated|unsupported|unreferenced`).
- Symlinks remain metadata; traversal, special files, malformed UTF-8, and oversize
  inputs degrade coverage visibly instead of failing silently.
- CLI: `plugins analyze PLUGIN_ID --format json` ships an inventory-only report through
  the extended envelope; text output stays bounded.
- Fixtures: bundled Python/shell executable plugin, binary payload plugin, symlinked
  payload, empty/malformed trees.
- Exit: a QML-invoking-bundled-Python plugin cannot produce an apparently clean report —
  the executable payload is inventoried with a visible unsupported-language state before
  any language analyzer exists.

### S2 — Parser spike, measurement, and ADR · Size M · maps to M3

- Prerequisite: generate a small pinned entry-point corpus manifest (~50 community
  plugins keyed by `upstreamObservedCommit`, with repository/layout/manifest path) from
  the frozen catalog snapshot, cloned into disposable cache at measurement time. The
  checked-in fixture holds two synthetic entries and cannot ground the coverage numbers;
  the full 653-plugin corpus remains S6.
- Integrate `tree-sitter-qmljs` behind a crate feature; parse pinned marketplace
  entry points and relevant QML files; measure byte/line span coverage.
- Evaluate against the kill criterion: ≥99% entry-point files, ≥95% all relevant QML
  without material uncovered regions.
- Probe `qmllint --json` as an optional correctness/import signal only (never the
  capability engine); keep QQmlSA documented as a future option, not a dependency.
- Write `docs/adr/0001-qml-parser.md`: chosen parser, measured coverage numbers,
  unsupported-syntax behavior, lexical-fallback semantics, and report metadata fields
  exposing parser version and fallback state.
- Exit: ADR merged; on kill, S3+S4 proceed with explicitly labelled lower-confidence
  lexical detection and the success-metric claim adjusts accordingly.

### S3 — Embedded-JS analysis, first capabilities, invocation edges · Size L · maps to M6 start, completes M2

- Extract and analyze embedded JavaScript from parsed QML (and standalone `.js`
  resources) with byte/line-span evidence.
- First high-signal capability rules: `Quickshell.Io.Process`, `execDetached`,
  `FileView`, networking imports/usages — capability ≠ finding; findings require
  suspicious data/command provenance per the rule contract.
- Invocation edges: resolve literal/local-path QML references to bundled payload files
  without following symlinks or leaving the logical repository root; mark referenced
  payloads; computed/dynamic sinks become explicit low-confidence findings.
- Analysis fingerprint wired end-to-end: identical source+policy ⇒ identical
  fingerprint; golden tests pin this from day one.
- Wire `--fail-on SEVERITY` for `plugins analyze`/`scan-plugin` per the report contract
  (findings are still success; CI opts into failure thresholds) with exit-code semantics
  documented separately from `scan`'s actionable-result exit code.
- Exit: every emitted result carries stable rule ID, evidence span, explanation,
  confidence, and review guidance; the S1 bundled-executable fixture now also exposes
  its invocation edge.

### S4 — Full rule set and priority surfaces · Size L · maps to M6 completion, M5 mappings

- Near-zero-legitimacy third-party rules: polkit agent, PAM/session-lock context,
  `WlSessionLock`/lock-surface access — careful evidence, manual-triage guidance.
- Remaining capability rules: clipboard monitoring, timers/background services,
  persistence patterns, Hyprland/Wayland control surfaces, dynamic code construction,
  encoded/obfuscated payload indicators.
- Minimal shell/Python lexical rules for high-signal constructs only; those files are
  labelled `partial`; no match never implies clean behavior.
- Plugin-kind context capabilities (`replaces the bar`, headless service persistence
  context) affecting review priority, never severity by themselves.
- Marketplace Baseline v4 equivalence mapping file (external system, rule-set version,
  external rule ID, verified-at commit) with staleness marking when the external
  definition moves.
- Severity table v1 finalized; rule meanings frozen behind policy identity.
- Exit: every rule maps to a verified sink or payload edge with a supported version
  range; fixtures exist positive/negative/boundary per rule family.

### S5 — Suppressions, event separation, determinism canary · Size M · maps to M4 remainder

- Scoped suppressions in XDG config: rule ID + target/path scope + human reason +
  creation time; suppressions never alter stored findings, only presentation/enforcement.
- Scan/alert integration: source drift, analyzer-policy updates (re-evaluation notice),
  and fingerprint-instability (nondeterminism error) are distinct events with distinct
  wording; registry claims still cannot clear local signals.
- `scan --include-analysis` (opt-in) adds new-capability/regression alerts with
  deduplication; default scans stay quiet unless opted in.
- `rules explain RULE_ID`; suppression flows through new `plugins review` actions:
  `--action suppress|reinstate --rule RULE_ID [--path SCOPE] --reason TEXT --yes`,
  persisting `{rule ID, target/path scope, reason, creation time}` in XDG config. The
  argv parser's existing scope enum (source-drift/missing-plugin/lost-coverage) is
  extended for rule/path scoping rather than overloaded; suppressions never alter
  stored findings, only presentation/enforcement, and are reinstateable/auditable.
- CI determinism canary: run analysis twice on pinned fixtures; any fingerprint
  mismatch fails the build with preserved repro inputs.
- Exit: tool-version/prose-only bumps preserve fingerprints; policy changes are labelled
  analyzer improvement; unchanged source+policy yields byte-identical normalized results.

### S6 — Pinned corpus, FP budget, validator parity · Size L · maps to M5 canary, M7

- Generate `fixtures/corpus/manifest.json` from the 653-community-plugin catalog
  snapshot: plugin ID, pinned `upstreamObservedCommit`, repository, layout, manifest
  path, expected availability. No plugin content is committed; CI clones pinned commits
  into disposable cache. Live-catalog refresh stays a separate scheduled job, never PR
  input.
- Expectation ledger keyed `{plugin_id, commit, rule_id}` (dispositions begin accruing
  during S3/S4 development; S6 industrializes the runner).
- Runners: representative pinned subset on every PR (bounded); full corpus nightly and
  pre-release; publish per-rule TP/FP/untriaged/incomplete counts.
- CI provisioning owned explicitly: the nightly workflow file, runner/network/cache
  budgets, an unavailable-repository policy (counted incomplete, never clean), and
  publication of corpus/parity reports as artifacts. Validator parity runs against the
  recorded Omarchy version via the VM harness or a pinned container — not assumed from
  bare `ubuntu-latest`; this is the release's largest recurring ops cost for a solo
  maintainer and is sized as such.
- Release gates: zero known high-severity false positives and zero untriaged
  high-severity results — not zero genuine findings.
- Manifest checks for plain Arch use implemented; parity canary runs both OmaSafe and
  native `omarchy plugin validate` over the pinned corpus and fails the build on
  disagreement for the recorded Omarchy version; newer unverified runtimes degrade
  validator coverage visibly at runtime instead of silently passing.
- Exit: high-severity policy has an auditable corpus record; incomplete repos cannot be
  counted as clean.

### S7 — Reviewed update workflow · Size L · maps to M8

- `plugins review-update ID`: refuse on dirty installed worktree; fetch candidate into
  the bounded cache; correlate exact commit against pinned registry claims; run OmaSafe
  analysis + native validation on the candidate; present the delta versus the trusted
  baseline (not the updater's HEAD-text diff).
- Explicit approval gate: interactive preview by default; `--yes` is accepted only
  together with `--expected-commit SHA` (mirroring the v0.1 unattended-trust rule).
  Then delegate mutation to `omarchy plugin update ID --yes`
  (fetch/fast-forward, native validation, native rollback via `git reset --hard
  ORIG_HEAD`, `rescanPlugins`) — never fork its lifecycle logic.
- Postconditions: installed `HEAD` must equal the exact reviewed commit and rescan must
  pass before the plugin is re-enabled / bar restored / trusted. Because today's native
  updater lacks an expected-SHA guard, raced candidates leave the plugin disabled with
  recovery guidance; propose the upstream expected-commit option separately.
- Interrupted-state recovery records and clear manual guidance for failures the native
  command cannot undo; continue detecting native-updater changes made outside OmaSafe.
- Test matrix: reject-before-mutation, active service, full-bar switch, dirty tree,
  invalid manifest, native-validation failure (native rollback path), rescan failure,
  raced commit, interruption mid-flow.
- Exit: rejected candidates never modify the live tree; only the reviewed commit can be
  enabled/trusted.

### S8 — UI, packaging, release · Size M · maps to M9

- Panel views (sibling `omasafe-plugin` repo): capabilities, payload inventory,
  invocation edges, findings with confidence, coverage limitations; bar badge remains a
  count/state — never a grade. All CLI invocations argv-style with bounded JSON parsing.
- Man pages/completions regenerated; signed tag + Sigstore-signed artifacts;
  publish self-scan, corpus report, and validator-parity report with the release.
- Cancellation and interruption safety for long-running commands (`plugins analyze`,
  `scan-plugin`, `review-update`): signal handling, atomic-write cleanup, and no partial
  state left behind; bounded JSON/text output (M9 requires cancellation explicitly).
- Clean-VM lifecycle tests: install/upgrade/downgrade/uninstall, panel lifecycle,
  schedule coexistence, third-party-bar notification independence.
- Release gate: the checklist in [README.md](README.md) ("Release Gate Used by Every
  Version") applies verbatim.

## Risks and Mitigations

- **tree-sitter-qmljs gaps/rot** → S2 kill criterion and ADR; lexical fallback keeps the
  release shippable; parser version is part of policy identity so swaps are explicit.
- **Corpus licensing** → store only manifests/digests/expectations in-repo; clone pinned
  commits at CI time; never redistribute plugin content.
- **Solo-maintainer throughput** → slices are independently shippable; S1–S6 deliver the
  full analysis value on their own if capacity forces re-scoping. As planned, S7 remains
  required for the v0.2 release outcome.
- **Corpus CI operations** → cloning/triaging 653 repositories is the largest recurring
  cost; the S6 unavailable-repository policy, cache quotas, and artifact budgets bound it,
  and the nightly job is allowed to fail loudly without blocking PRs.
- **Native updater lacks expected-SHA guard** → postcondition design keeps the plugin
  inactive on any mismatch; limitation stated in docs and proposed upstream.
- **False-positive pressure on high-signal rules** → expectation ledger plus release
  gates; suppressions are scoped and auditable, never silent defaults.
- **Fingerprint nondeterminism** → golden tests from S3 onward and the S5 CI canary.

## Success Metrics (from v0.2.md, owned per slice)

- 100% relevant shipped files receive an inventory/coverage state → S1.
- ≥99% entry-point / ≥95% all-QML parser coverage, or explicit reduced lexical claims → S2.
- Every result has ID/evidence/confidence/guidance → S3/S4.
- Zero unexplained fingerprint changes in CI → S5.
- Zero known high-sev FPs; zero untriaged high-sev corpus results → S6.
- 100% agreement with native manifest validation for the recorded corpus/version → S6.
- Every QML→bundled-executable fixture exposes the invocation edge → S3.
