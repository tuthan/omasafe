# v0.2.2 Candidate Source Scan Implementation Plan

Status: revised draft for maintainer approval, 2026-09-04 · Owner: Hung Vo · Scope source:
user-requested pre-install review of GitHub and marketplace candidates

This release lets an operator ask OmaSafe to analyze a plugin before it is installed. The
primary UI workflow accepts either a public GitHub repository URL or the plain-text install
command copied from the marketplace, for example:

```text
https://github.com/wkuehler/omarchy-restic-monitor.git
omarchy plugin add https://github.com/wkuehler/omarchy-restic-monitor.git --enable
```

Both inputs resolve to one exact Git commit before analysis. OmaSafe downloads only into its
bounded XDG cache, reads the exact candidate without executing it, and does not call
`omarchy plugin add`, write under `~/.config/omarchy/plugins`, enable a plugin, or create a
trust baseline.

The implementation is decomposed into vertical slices `C0`–`C4`. Each slice ends committed
and verified per [`../progress.md`](../progress.md), leaves existing v0.2.1 commands working,
and either delivers an end-to-end candidate workflow or retires a release-blocking input
boundary.

## Outcome

An operator can paste a marketplace install command into the OmaSafe panel, press **Scan
candidate**, and receive a report that visibly separates:

1. what input was recognized;
2. which immutable commit was actually analyzed;
3. what network and cache work occurred;
4. which findings and capabilities the analyzer reported;
5. what coverage was partial, skipped, unsupported, or omitted from the compact view; and
6. that no installation, enable, trust, suppression, or lifecycle action occurred.

The successful empty-finding state reads **“No active findings under this scan's reported
coverage”**, never “safe”, “clean”, “approved”, or “ready to install”.

## Strategy Decisions

1. **The CLI owns pasted-input parsing.** QML performs only empty/length checks for user
   feedback and passes the complete field value as one argv item. `omasafe-cli` recognizes a
   deliberately small grammar, extracts exactly one public HTTPS GitHub repository URL, and
   never starts a shell or invokes `omarchy`. The agent skill uses the same route rather than
   duplicating the parser.
2. **Moving input resolves to immutable evidence.** A raw GitHub URL or copied install command
   names mutable default-branch HEAD. OmaSafe resolves HEAD once, records the full advertised
   commit, fetches that exact commit, and analyzes only its raw Git objects. The report keeps
   the moving request distinct from the resolved commit.
3. **Exact input remains the strongest route.** Existing
   `scan-plugin --git URL --revision COMMIT` behavior stays supported and unchanged. The new
   convenience route does not weaken exact-revision review or make a later mutable native
   install equivalent to the scanned commit.
4. **Candidate scan is never installation.** Candidate acquisition may write disposable
   objects under `${XDG_CACHE_HOME:-~/.cache}/omasafe/analysis`, but it writes no installed
   plugin tree, trust history, review decision, override, enable state, schedule, scan alert,
   or notification state. There is no Install button or scan-to-install continuation in this
   release.
5. **Integrity and analyzer results are separate.** A verified commit says which Git objects
   were scanned, not whether those objects are benign. Marketplace verification, findings,
   capabilities, coverage, and human trust remain separate report fields and UI sections.
6. **Legacy marketplace and future registry are different sources.** v0.2.2 may resolve an
   existing marketplace plugin ID through the already pinned Git catalog. The future hosted
   Omarchy registry uses signed indexes and immutable tarballs; both archive ingestion and
   remote archive transport are deferred to a later release for a standalone dependency and
   threat-model review.
7. **Candidate findings are explicitly unsuppressed.** `plugins analyze` retains configured
   suppression behavior. Every `scan-plugin` route selects `candidate-unsuppressed`, does not
   load or match suppression records, and reports the complete internal finding set before
   review-profile shaping. Today this changes only hand-edited global (`plugin_id: null`)
   records because CLI-created suppressions are plugin-scoped; the explicit policy prevents
   `--plugin-id` from accidentally widening that behavior later.
8. **One compact, actually bounded consumer profile.** `--report-profile review` preserves
   identity, totals, findings, capabilities, invocation edges, fingerprints, and limitations,
   but omits payload entries and deterministically caps the remaining repeated JSON lists with
   total/emitted/omitted counts. The final pretty-printed JSON is preflighted against a byte
   ceiling below both consumer transport limits. The panel and agent skill use this profile;
   direct CLI JSON remains `full` by default and remains unbounded by this new profile.
9. **No remote archive dependency expansion in v0.2.2.** The existing `git` subprocess remains
   the only network acquisition mechanism. HTTPS/TLS, HTTP, tar, and gzip dependencies do not
   enter this release; archive work moves to a later candidate-acquisition release, where
   dependency count, licenses, advisories, update cadence, and artifact/self-scan impact are
   review gates of their own.
10. **No new workspace crate.** Source parsing/cache primitives live in `omasafe-core`, legacy
    catalog resolution in `omasafe-marketplace`, typed acquisition output in `omasafe-report`,
    and orchestration in `omasafe-cli`.

## Maintainer Review Gates

- Approve `--request TEXT` as the shared raw-URL/copied-command UX rather than parsing the
  command separately in QML and the agent skill.
- Approve default-HEAD resolution for a read-only scan while retaining exact commit as the
  only reproducible input and displaying the resolved commit before any later human action.
- Approve public GitHub-only parsing for `--request` in v0.2.2. Other HTTPS Git servers remain
  available through explicit `--git`; private repository credentials remain out of scope.
- Approve the explicit `candidate-unsuppressed` policy and its narrow behavior change for
  hand-edited global suppression records used with existing `scan-plugin --path` / `--git`
  callers.
- Approve refusing unverified cached catalog bytes as a network-resolution source. A stale but
  cryptographically reverified snapshot may resolve its recorded exact commit with visible age.
- Approve canonicalizing only exact public GitHub SSH/scp-style catalog repository values to
  HTTPS while preserving the original owner/repository case. Other SSH/private catalog sources
  fail with a specific unsupported-source error.
- Approve deferring `--registry publisher/name@version` until the official Omarchy client
  signing key, index format, freshness rules, and revocation behavior are shipped and pinned.
- Approve the candidate panel as a transient review surface with no install, trust, enable,
  override, notification, or periodic-scan action.
- Approve moving local and remote archive acquisition to a later release rather than adding a
  large HTTP/TLS/archive dependency surface to this focused release.

## Input Grammar and Parsing Contract

### Accepted `--request` forms

After trimming leading and trailing ASCII whitespace, input is limited to 4,096 UTF-8 bytes and
must be exactly one line matching one of these forms:

```text
GitHubUrl      := https://github.com/OWNER/REPOSITORY[.git][/]
InstallRequest := [$] omarchy plugin (add | install) GitHubUrl InstallFlag*
InstallFlag    := --enable | --yes
```

Whitespace between install-command tokens is one or more ASCII spaces or tabs. The optional
leading `$` accommodates documentation prompts. Flags are accepted in any order at most once,
recorded as discarded install intent, and never applied. The parser returns a typed value:

```text
ParsedCandidateRequest {
    input_kind: raw-github-url | omarchy-install-command,
    install_verb: none | add | install,
    repository_url: canonical public HTTPS GitHub URL,
    discarded_install_flags: [enable | yes],
}
```

URL validation requires:

- scheme exactly `https`;
- host exactly `github.com` (case-insensitive before canonicalization), with no userinfo or
  non-default port;
- exactly two non-empty path segments after percent-decoding checks;
- repository name with one optional terminal `.git`, normalized to one `.git` suffix;
- no query, fragment, control character, encoded separator, `.`/`..`, or empty owner/repo; and
- a canonical URL small enough for report, cache-key, Git argv, and UI bounds.

### Rejected input

The request parser rejects rather than partially accepting:

- newline-separated commands, comments, environment assignments, or leading wrappers such as
  `sudo`, `env`, `sh -c`, `bash -c`, `command`, or aliases;
- shell operators or substitutions: `;`, `&&`, `||`, pipes, redirections, backticks, `$()`,
  process substitution, globs, or command continuations;
- quoted/token-concatenated URLs, Markdown link syntax, HTML, code fences, or prose surrounding
  the command;
- more than one URL, a URL in an option value, positional arguments after the repository, an
   unknown flag, or a flag that takes a value;
- SSH, `git://`, `http://`, `file://`, GitHub tree/blob/archive/release paths, shortened URLs,
  credential-bearing URLs, and private access tokens; and
- registry coordinates or archive URLs. Those use future dedicated selectors, never
  content-type guessing in `--request`.

Errors identify the rejected category and give the safe correction, for example “Paste only
the GitHub repository URL or a plain `omarchy plugin add|install URL --enable` command.” An
unknown flag-shaped token is named after bounded escaping (for example, “unsupported install
flag: `--force`”) so a copied documented command can be debugged without echoing the whole
untrusted input.

### Parser implementation

- Hand-write the finite grammar over bounded ASCII tokens; do not add a shell parser.
- Parse to a typed enum before any network or cache operation.
- Unit-test the parser without Git/network access, including every separator/control character
  and mixed Unicode whitespace/confusable case.
- QML must not trim tokens, extract substrings, use a URL regex as an authority, or construct a
  shell command. It calls:

  ```text
  omasafe-cli scan-plugin --request INPUT --report-profile review --format json
  ```

  where `INPUT` is one argv element created by the existing argv-only CLI launcher.

## CLI Surface

Regenerate the man page and completions through `scripts/generate-cli-assets.sh` after updating
`docs/cli-surface.txt`.

```text
scan-plugin
    (--path DIR
     | --git URL [--revision COMMIT]
     | --request TEXT
     | --marketplace PLUGIN_ID)
    [--plugin-id PLUGIN_ID]
    [--report-profile full|review]
    [--format text|json]
    [--fail-on info|low|medium|high|critical]
```

Argument rules:

- The four primary selectors are mutually exclusive.
- `--revision` is valid only with `--git`; absence means resolve default-branch HEAD once.
- `--plugin-id` is valid for `--path`, `--git`, and `--request`. It selects a unique manifest
  root inside a monorepo and is implied by `--marketplace`. It is selection metadata only and
  must never be passed as `plugin_context` or otherwise enable configured suppressions.
- `--report-profile` defaults to `full`. `review` is additive report shaping only and cannot
  change analysis, fingerprint, policy, severity, `--fail-on`, or coverage semantics.
- Findings remain successful scan output. Exit `4` remains exclusive to an explicit
  `--fail-on` threshold. Request-parser, acquisition, missing-value, unknown-option, and
  selector-shape failures all use exit `1`, matching today's recognized-command behavior.
  Exit `2` remains only the top-level dispatch/usage fallthrough; changing argv errors across
  every subcommand is not part of this release. Interrupts use `130`.

Examples:

```sh
# UI/agent-friendly raw URL or copied command
omasafe-cli scan-plugin --request \
  'omarchy plugin add https://github.com/wkuehler/omarchy-restic-monitor.git --enable' \
  --report-profile review --format json

# Reproduce the resolved candidate exactly
omasafe-cli scan-plugin \
  --git https://github.com/wkuehler/omarchy-restic-monitor.git \
  --revision FULL_COMMIT --format json

# Resolve a listing from the already verified cached marketplace snapshot
omasafe-cli marketplace refresh --commit CATALOG_COMMIT
omasafe-cli scan-plugin --marketplace PLUGIN_ID --format json
```

## Acquisition and Identity Contract

### GitHub/default HEAD

1. Parse and canonicalize the request without network access.
2. Resolve the repository's symbolic HEAD and full commit with bounded argv-only
   `git ls-remote --symref URL HEAD` under the hardened Git environment in
   `omasafe-core::git`.
3. Require one valid symbolic default branch and one full 40- or 64-hex commit mapping. Reject
   ambiguous, detached/malformed, truncated, timed-out, credential-prompting, or non-UTF-8
   output.
4. Fetch only the resolved commit through the existing private bare-cache path with no tags,
   hooks, checkout, submodules, filters, LFS, optional locks, or credential prompt.
5. Before reusing a URL-slugged bare cache, query and require its object format to match the
   resolved commit length. A mismatch fails visibly or rebuilds only that exact cache entry
   under the global cache lock; it never fetches into a repository initialized for the other
   object format.
6. Read the full tree as raw objects. The report's `target.revision` is always the exact
   resolved commit, never `HEAD`, a branch, a tag, or “latest”.
7. If HEAD moves between resolution and fetch, fetching the recorded commit either succeeds
   and scans that commit or fails visibly. It never silently substitutes the newer HEAD.

Move the existing remote-HEAD resolver from marketplace-specific ownership into a bounded
`omasafe-core` primitive and reuse it for both marketplace refresh and candidate scanning.
This also removes the remaining unbounded `Command::output()` form from that resolution path.

### Legacy marketplace ID

1. Load the cached catalog and require `snapshot.verified == true`; an unverified local cache
   may be displayed as context but cannot direct a network fetch.
2. Match `PLUGIN_ID` exactly and require one entry, one supported public repository, and one
   full `listingValidatedCommit`. Never substitute `upstreamObservedCommit` or live HEAD.
3. Accept a strict credential-free HTTPS URL, or the exact GitHub SSH/scp shapes
   `git@github.com:OWNER/REPO[.git]` and `ssh://git@github.com/OWNER/REPO[.git]`. For the latter,
   parse the original catalog value without case-folding and construct
   `https://github.com/OWNER/REPO.git`. Do not use `normalize_repository` as the fetch-URL
   authority because it lowercases owner/repository segments. Reject other SSH/private forms
   with `unsupported-marketplace-repository`, not a repository-layout error.
4. Preserve both `listed_repository` (attributed catalog text) and
   `effective_repository_url` (canonical fetch URL) in acquisition output so the conversion is
   visible. Never silently rewrite one into the other.
5. Attribute `verificationStatus`, listing commit, catalog repository commit, catalog digest,
   retrieval time, generation time, and age to the marketplace snapshot. Verification status
   does not suppress findings or establish safety.
6. Discover `manifest.json` candidates directly in the exact Git tree under existing
   file/depth/time limits. Parse only bounded manifest bytes and require exactly one manifest
   whose `id` equals the requested plugin ID.
7. Scan that manifest root as the logical plugin root. Zero or multiple matches, an unsupported
   repository layout, a mismatched manifest ID, or incomplete discovery is an acquisition
   failure, not a repository-wide apparently successful scan.

## Report Contract

Keep the outer `omasafe.report.v1` and `result.analysis.schema == omasafe.analysis.v1`. Add a
typed, required-for-remote-candidates acquisition section:

```json
{
  "target": {
    "source": "resolved-git-request",
    "id": "io.example.plugin",
    "url": "https://github.com/example/plugin.git",
    "revision": "0123456789abcdef0123456789abcdef01234567",
    "scope": "plugin-root",
    "root": ""
  },
  "acquisition": {
    "schema": "omasafe.acquisition.v1",
    "operation": "scan-only",
    "installation_performed": false,
    "input_kind": "omarchy-install-command",
    "install_verb": "add",
    "requested_reference": "default-branch-head",
    "resolved_identity": {
      "kind": "git-commit",
      "value": "0123456789abcdef0123456789abcdef01234567"
    },
    "integrity": {
      "state": "resolved-exact",
      "algorithm": "git-sha1",
      "expected": null,
      "observed": "0123456789abcdef0123456789abcdef01234567"
    },
    "network_used": true,
    "cache": { "used": true, "result": "hit" },
    "discarded_install_flags": ["enable"],
    "marketplace_claim": null,
    "limitations": []
  }
}
```

Every analyzer result also carries an explicit suppression policy:

```json
{
  "suppressions": {
    "policy": "candidate-unsuppressed",
    "consulted": false,
    "applied": [],
    "reconfirmation_required": [],
    "active_records": null
  }
}
```

`plugins analyze` uses `policy: "configured"`, `consulted: true`, and its existing active and
applied record semantics. All `scan-plugin` selectors use `candidate-unsuppressed`, including
`--path` and exact `--git`; `--plugin-id` cannot change it.

Required enums:

- `target.source`: existing `installed-plugin|local-directory|pinned-revision`, plus
  `resolved-git-request|marketplace-listing`;
- `acquisition.operation`: only `scan-only` in v0.2.2;
- `acquisition.input_kind`: `raw-github-url|omarchy-install-command|exact-git|marketplace-id`;
- `acquisition.install_verb`: `none|add|install`;
- `resolved_identity.kind`: only `git-commit` in v0.2.2;
- `integrity.state`: only `resolved-exact` in v0.2.2;
- `suppressions.policy`: `configured|candidate-unsuppressed`, with `consulted` required to
  match the policy invariant described above;
- `cache.result`: `not-used|hit|miss`.

Never include the full pasted command, cache filesystem path, Git stderr containing remote
text, or target file contents. The canonical repository URL, exact commit, bounded source
label, install verb, and discarded flag names are sufficient evidence.

`--report-profile review` keeps the same envelope and schemas but changes
`payload_inventory` to:

```json
{
  "totals": { "files_seen": 10, "bytes_ingested": 2048, "entries": 10 },
  "coverage_states": {},
  "limitations": [],
  "entries": [],
  "entries_omitted": 10,
  "profile": "review"
}
```

The review profile adds a required shaping summary:

```json
{
  "report_profile": {
    "name": "review",
    "serialized_byte_limit": 1572864,
    "omissions": {
      "payload_entries": { "total": 10, "emitted": 0, "omitted": 10 },
      "findings": { "total": 3, "emitted": 3, "omitted": 0 },
      "capabilities": { "total": 4, "emitted": 4, "omitted": 0 },
      "invocation_edges": { "total": 2, "emitted": 2, "omitted": 0 }
    }
  }
}
```

There is no existing JSON output cap: the current 200-entry and 100-finding constants apply
only to text rendering. C1 therefore adds a real review-profile JSON byte limit. Lists remain
deterministically sorted, are initially capped by documented per-list limits, and are reduced
from their tails if exact pretty serialization still exceeds 1,572,864 UTF-8 bytes. Each
reduction updates total/emitted/omitted and adds a coverage limitation. Required schemas,
target/acquisition identity, totals, policy identity, fingerprint, and suppression policy are
never removed. If the mandatory envelope alone exceeds the limit, exit `1` before writing any
JSON. A consumer may render the no-active-findings state only when the findings omission count
is zero and coverage permits it. Analysis fingerprint and `--fail-on` are always computed from
the complete internal result set before shaping.

## Slices

### C0 — Pasted request to exact Git report · Size M

This is the user-visible MVP and must land end-to-end before marketplace-ID work.

- Add the bounded `ParsedCandidateRequest` grammar and public GitHub URL canonicalization in
  `omasafe-core::source`, including both real `omarchy plugin add` and documented
  `omarchy plugin install` forms with only `--enable` and `--yes`.
- Add `scan-plugin --request TEXT` and allow `--git URL` without `--revision` to resolve remote
  HEAD once. Reuse the current exact fetch/raw-object analyzer after resolution.
- Move marketplace's HEAD-resolution logic into the shared hardened Git module and replace its
  unbounded process capture with the common bounded runner.
- Before reusing a URL-slugged bare repository, verify its Git object format against the
  resolved revision length; test pre-planted SHA-1/SHA-256 format mismatches.
- Add `omasafe.acquisition.v1` with `scan-only`, exact resolved identity, network/cache facts,
  install verb, discarded install flags, and explicit `installation_performed: false`.
- Split report emission suppression handling into `configured` and `candidate-unsuppressed`.
  The latter never loads/matches records, emits `consulted: false`, and uses the complete
  rendered findings for `--fail-on`. Keep `--plugin-id` strictly outside `plugin_context`.
- Tests cover raw URL, add/install commands, optional `$`, accepted flag ordering, named
  unknown-flag errors, exact resolved commit, moving HEAD after resolution, cache hit/miss, no
  installed/state writes, hand-edited global suppressions, and the full rejected grammar
  matrix.
- Exit: the example install command produces a valid analysis report for one exact commit;
  neither the test plugin directory nor shell configuration changes.

### C1 — Compact review transport · Size S

- Add `--report-profile full|review`; full output preserves complete-list behavior. The release
  makes only versioned additive acquisition/suppression fields outside review-profile shaping.
- Omit payload entries and add explicit total/emitted/omitted counts for entries, findings,
  capabilities, and invocation edges. Retain coverage, policy identity, analysis fingerprint,
  suppression policy, and immutable acquisition identity.
- Add deterministic initial list caps followed by an exact pretty-serialized UTF-8 preflight
  at 1,572,864 bytes. If necessary, trim repeated lists from their sorted tails, update omission
  counts/limitations, and serialize again; if mandatory fields alone cannot fit, fail before
  emitting JSON.
- Update CLI integration tests for full/review semantic equivalence, fingerprint equality,
  threshold equality, deterministic ordering, mandatory-field preservation, and bounded
  output. Include independent pathological fixtures for 10,000 inventory entries, maximum
  findings, maximum capabilities, maximum edges, and large bounded strings.
- Exit: every successful review report is at most 1,572,864 serialized UTF-8 bytes and carries
  omission counts; it never becomes an apparent complete or empty-finding result after shaping.

### C2 — Legacy marketplace plugin-ID resolution · Size M

- Add `omasafe-marketplace::resolve_candidate(snapshot, plugin_id)` returning typed catalog
  identity, repository, exact listing commit, declared layout, and attributed claims.
- Require a reverified cached snapshot before using catalog-controlled URL/commit values for a
  fetch. Preserve visible staleness without silently refreshing.
- Parse supported HTTPS repository URLs directly. Convert only exact GitHub SSH/scp catalog
  forms to credential-free HTTPS while preserving original path case; include both the listed
  value and effective fetch URL in acquisition output. Reject every other SSH/private form with
  a source-specific error.
- Add bounded exact-tree manifest discovery and unique plugin-root selection for root,
  monorepo, and suite layouts.
- Add `scan-plugin --marketplace PLUGIN_ID`; feed its resolved repository/commit/root into the
  same Git analyzer and include `marketplace_claim` in acquisition output.
- Tests cover no cache, unverified/tampered cache, stale verified cache, missing/duplicate ID,
  missing/invalid listing commit, HTTPS and GitHub SSH fixture values, case preservation,
  rejected non-GitHub SSH/private sources, repository conflict, zero/multiple manifest matches,
  traversal-like manifest paths, and source-wide files outside the selected root.
- Exit: a listing scan is reproducible from catalog commit + catalog digest + repository commit
  and never silently scans live upstream HEAD.

### C3 — OmaSafe plugin candidate view · Size M · sibling repository

- Freeze the C0–C2 JSON contract in `../omasafe-plugin/docs/cli-v0.2.2-plan.md` before QML work.
- Keep the configurable general CLI minimum for older panel features, but add a hard candidate
  feature minimum of `0.2.2` and change `cliVersionMin`'s manifest default to `0.2.2`. Hide or
  disable **Scan candidate** with an upgrade explanation when the resolved CLI is older,
  malformed, missing, or fails the required identity check; never invoke `--request` on 0.2.1.
- Add a **Scan candidate** action from Overview that opens a dedicated view/sheet, not an
  installed-plugin row and not a new trust action.
- Provide one multiline-safe-but-single-request text control labelled **GitHub URL or copied
  install command** with the example placeholder. Standard paste/`Ctrl+V` is sufficient;
  v0.2.2 does not read the clipboard automatically and therefore adds no clipboard capability.
- QML checks empty input and may show a 4,096-character advisory hint, but the CLI's 4-KiB
  UTF-8 byte check is authoritative because QML string length counts UTF-16 code units. QML
  passes the value as one argv item to `--request` and displays CLI-authored parse errors. It
  never extracts the URL, tokenizes the command, or invokes the pasted command.
- Add a dedicated bounded Process: 120-second timeout, existing two-phase TERM→KILL shutdown,
  2 MiB-character cap per stream (matching `v02OutputCharCap`), first-terminal latch, and
  request-generation token so stale completion cannot replace a newer result.
- Candidate view states: `idle|resolving|fetching|analyzing|complete|unavailable|cancelled`.
  Progress before final JSON is generic because the CLI emits one committed report, not
  untrusted streaming target text.
- Normalize only reports with `omasafe.report.v1`, `omasafe.analysis.v1`, and
  `omasafe.acquisition.v1`; require `operation == scan-only` and
  `installation_performed == false`, plus `suppressions.policy == candidate-unsuppressed` and
  `suppressions.consulted == false`. Unknown schemas/enums render unsupported, never quiet.
- Result hierarchy: resolved repository + full/copyable commit, “not installed” operation
  status, integrity/cache facts, findings, capabilities, coverage, limitations, then a copyable
  exact rescan command. Do not render the original command or raw target instructions.
- Do not show Install, Enable, Trust, Review, Suppress, Override, Update, or “Continue” actions.
  Closing the panel cancels the process and clears pasted input/result unless a later explicit
  history feature is approved.
- Cache only in memory by `{resolved identity, policy identity, report profile}` during the
  current panel session. Never key by mutable URL and never persist pasted input.
- Validate with `qmllint`, `omarchy plugin validate .`, fixture-driven view-model tests, hostile
  report strings/control characters, output-cap/timeout/cancel races, keyboard navigation,
  narrow/expanded layouts, and the clean-VM supported-runtime harness.
- Exit: pasting the example marketplace command renders the exact resolved commit and analysis
  without installing or enabling the plugin; invalid/piped commands render a local CLI error.

### C4 — Agent skill, documentation, and release · Size M

- Update `omasafe-plugin-review` to require CLI `>= 0.2.2` for candidate-request, marketplace,
  and review-profile routes while retaining v0.2.1 behavior for installed/local/exact-Git work.
- Add routes:
  - user-supplied raw URL or copied command → `scan-plugin --request INPUT`;
  - exact Git URL + commit → existing `--git URL --revision COMMIT`;
  - marketplace ID → `--marketplace ID` only with the CLI-owned verified cache decision;

## Security Test Matrix

### Pasted command/parser

- Raw URL with/without `.git` or trailing slash; mixed-case host canonicalization.
- Marketplace `add` and `install` commands with no flags and every allowed flag order;
  duplicate allowed flags and invented `--unsafe` are rejected.
- Optional leading `$`; leading/trailing ASCII whitespace; tab separators.
- Newlines, CRLF second command, NUL/control characters, Unicode whitespace/confusables.
- `;`, `&&`, `||`, pipe, redirects, backticks, `$()`, `${}`, process substitution, globbing,
  comments, escaped newline, quotes, concatenated tokens, Markdown/HTML/code fences.
- Multiple URLs, unknown/value-taking flags, pre-command env/sudo/wrappers, arguments after URL.
- HTTP/SSH/file/git schemes, credentials, token query, fragment, custom port, tree/blob/archive
  GitHub routes, percent-encoded separators/traversal, empty/extra path segments.
- Recognized-command parser/argv failures exit `1`; only unknown top-level dispatch exits `2`.

### Resolution/cache

- Valid SHA-1 and SHA-256 repositories; malformed/multiple/truncated `ls-remote` output.
- HEAD changes after resolution; resolved commit disappears; repository renamed/deleted.
- Prompting auth, hostile Git environment/config, hooks, filters, LFS, submodules, ext protocol.
- Cold/warm concurrent cache, quota pre/post breach, planted links/files, permission failure,
  timeout, SIGINT/SIGTERM, and stale incomplete object cleanup.
- Existing URL-slugged cache initialized as SHA-1 with a 64-hex resolution and SHA-256 with a
  40-hex resolution; neither case may fetch before format mismatch handling.

### Marketplace

- Valid exact listing; listing marked verified/unverified as an attributed claim.
- Verified, unverified, stale, malformed, rolled-back, or digest-mismatched catalog cache.
- Duplicate IDs/repos, invalid repository/commit, missing listing commit, unsupported layout.
- HTTPS listings, GitHub scp/SSH listings with mixed-case owner/repository, and rejected
  non-GitHub SSH/private listings; acquisition preserves listed and effective repository values.
- Root/monorepo/suite manifests; zero/duplicate/mismatched plugin IDs; discovery bound loss.

### Consumer/report

- Unknown/missing report or acquisition schema, enum expansion, malformed JSON, over-cap output,
  truncated summary, timeout, interrupt, and stale request completion all render unavailable.
- Missing/unknown suppression policy, `consulted: true` on a candidate, or non-empty candidate
  applications render unsupported rather than silently accepting filtered findings.
- Target strings containing terminal escapes, QML-like markup, bidi controls, URLs, Markdown,
  and instructions remain bounded text evidence and cannot become commands or UI markup.
- Full and review profiles have identical analysis/policy fingerprints, findings totals,
  threshold result, resolved source identity, and acquisition integrity.
- Pathological findings/capabilities/edges stay within the 1,572,864-byte review JSON limit with
  exact omission counts; mandatory-envelope overflow emits no partial JSON.
- CLI 0.2.1 keeps the candidate action disabled with an upgrade explanation. CLI 0.2.2 runs it
  under the existing 2 MiB-character QML stream guards.

## Risks and Mitigations

- **Pasted text becomes command execution** → finite grammar in `omasafe-core`, one argv item,
  no shell, no invocation of the parsed `omarchy` verb, exhaustive separator/control tests.
- **Default HEAD moves during review** → resolve once to a full commit, fetch only that commit,
  report it as the identity, and fail instead of substituting a newer HEAD.
- **A cached bare repository has the wrong object format** → inspect format under the global
  cache lock before fetch and rebuild only the exact URL cache entry or fail visibly.
- **Catalog repository conversion changes identity** → convert only strict public GitHub
  SSH/scp forms, preserve case from the original value, record listed and effective URLs, and
  reject all other private/SSH forms explicitly.
- **Verified catalog data is stale or attacker-controlled text** → require local digest/object
  reverification, attribute age and claims, and never treat catalog verification as a verdict.
- **Candidate findings are accidentally filtered** → typed suppression policy bypasses record
  loading/matching; consumers reject any candidate report that claims configured consultation.
- **Review JSON overruns QML or runner transport** → exact serialized-byte preflight below both
  limits, deterministic omissions, and no no-findings state when findings are omitted.
- **Panel and CLI versions drift across sibling releases** → hard 0.2.2 feature gate, frozen
  fixtures, unknown-schema refusal, and no `--request` invocation against 0.2.1.
- **The agent leaks or independently handles candidate content** → redact raw request metadata,
  use the CLI-only acquisition route, validate schemas/invariants, and retain bounded summaries.
- **Archive work quietly reintroduces a large dependency graph** → no archive selectors or
  HTTP/TLS/tar/gzip crates in v0.2.2; the later candidate-acquisition release starts with a
  standalone dependency bill and ADR.

## Success Metrics

- Both the documented `add` command and `install` alias resolve to the same exact commit and
  analysis fingerprint for the same repository state.
- Every shell-operator, multi-command, wrapper, unknown-flag, and multi-URL fixture is rejected
  before Git/cache access; the copied input is never executed or emitted in full.
- A HEAD race either analyzes the first resolved commit or fails; zero tests observe a silent
  substitution to the second commit.
- Before/after state fixtures show zero changes outside the bounded analysis cache for every
  successful and failed candidate request.
- Every `scan-plugin` JSON report says `candidate-unsuppressed`, `consulted: false`, and applies
  zero stored records, including with `--plugin-id` and a hand-edited global suppression.
- Every successful review-profile report is at most 1,572,864 UTF-8 bytes and its omission
  arithmetic is exact; full and review profiles retain the same complete-result fingerprint and
  `--fail-on` result.
- Marketplace fixtures cover HTTPS and mixed-case GitHub SSH/scp listings without losing
  provenance; unsupported private/SSH values fail with the named source error.
- On CLI 0.2.1 the panel runs no candidate process; on 0.2.2 the example completes within the
  character/time guards and renders the full resolved commit.
- The agent runner test proves `scan-plugin` receives the 4 MiB raw-stream cap, preserves
  omission totals in its 64 KiB summary, and redacts the raw `--request` value.
- The v0.2.2 `Cargo.lock` diff contains no new HTTP, TLS, tar, or gzip dependency stack.

## Acceptance Criteria

- Pasting
  `omarchy plugin add https://github.com/wkuehler/omarchy-restic-monitor.git --enable`
  in the plugin UI analyzes one exact full commit and shows that commit to the operator.
- The pasted text is passed as one argv item, parsed only by the CLI, and never evaluated by a
  shell or executed as `omarchy`.
- The documented `omarchy plugin install URL [--enable] [--yes]` alias is accepted; `--unsafe`
  and every other unknown flag are rejected with a bounded token-specific error and exit `1`.
- Before/after snapshots prove no candidate route changes installed plugin directories,
  enabled/bar state, trust/review/override history, schedule, alert state, or notifications.
- Every network scan reports whether network/cache were used and names an immutable resolved
  identity. No report target uses `HEAD`, a branch, a tag, “latest”, or a mutable URL as its
  resolved identity.
- Exact Git commit scans remain backward compatible and continue reading raw objects without
  checkout, hooks, filters, submodules, or LFS.
- Marketplace-ID scans are bound to a reverified cached catalog and its exact validated commit;
  catalog verification remains an attributed snapshot claim rather than a security verdict.
- Supported GitHub SSH/scp catalog values are converted to public HTTPS without case-folding;
  both listed and effective forms remain visible, and unsupported private forms fail explicitly.
- Candidate findings are not hidden by stored suppressions; reports and consumers require the
  explicit candidate-unsuppressed policy. Any report shaping or omission is counted and
  prevents an unqualified no-active-findings presentation.
- Review-profile JSON is hard-bounded by serialized UTF-8 bytes, not by inventory omission
  alone; findings, capabilities, and edges have exact omission accounting.
- The panel refuses candidate scanning below CLI 0.2.2, treats its input-length check as
  advisory, and enforces the existing output guard in characters.
- CLI, QML plugin, and agent runner reject unknown required schemas/enums and preserve error,
  unsupported, partial, stale, timed-out, interrupted, and truncated states.
- Documentation never calls a candidate safe, clean, malware-free, trusted, approved, or
  installable based on analysis. It always states that plugins run unsandboxed if later enabled.
- `cargo fmt`, both workspace test configurations, clippy, generated-asset check, determinism
  canary, bounded corpus sample, validator parity, self-scan, clean-VM plugin validation, and
  dependency advisory/license gates pass before tagging.

## Explicit Non-Goals

- Executing, rendering, importing, building, testing, or behaviorally detonating candidate code.
- Installing, enabling, updating, trusting, suppressing, overriding, or automatically approving
  a candidate after scan.
- Guaranteeing that native `omarchy plugin add URL` later installs the scanned commit; current
  native Git installation follows mutable HEAD and remains a separate human action/risk.
- Private GitHub repositories, credentials, cookies, auth headers, SSH agents, signed URLs, or
  enterprise GitHub hosts in v0.2.2.
- Generic shell-command parsing, Markdown scraping, prose URL extraction, multiple repositories,
  recursive marketplace commands, or accepting arbitrary installer syntax.
- ZIP, 7z, rar, OCI images, package-manager artifacts, nested archives, dependencies, or archive
  install receipts in v0.2.2. Local tar/tar.gz ingestion and remote archive fetching are also
  deferred in full to a later candidate-acquisition release.
- Hard-coding the future Omarchy registry URL templates, public key, signature algorithm details,
  semantic-version resolver, freshness generation, yank, or revocation policy before its client
  contract launches.
- Runtime sandboxing, antivirus/malware verdicts, official marketplace endorsement, or proof that
  future code at the same URL matches the reviewed bytes.

## Deferred Archive and Registry Work

The later candidate-acquisition release begins with a standalone dependency/threat-model decision
before code. It must compare a small local-archive implementation (for example, a bounded tar
reader plus a narrowly scoped inflate dependency) with maintained archive crates, and publish the
exact direct/transitive dependency, license, advisory, update-cadence, binary-size, self-scan, and
signed-artifact impact.
Remote archive support is a separate gate because a certificate-validating HTTPS stack adds a
materially larger supply-chain and protocol surface. Neither capability is an implied carry-over
from this plan.

After the official Omarchy registry client contract launches, add a separately reviewed source:

```text
scan-plugin --registry publisher/name[@version]
```

It must verify the pinned registry key, detached index signature, generation monotonicity,
expiry, version compatibility, yank state, signed revocation list, tarball size, and SHA-256
before passing bytes to that release's archive frontend. Browse API data may be displayed but can
never select install/scan bytes. This adapter should share conformance fixtures with the native
Omarchy client rather than independently interpreting a draft server implementation.
