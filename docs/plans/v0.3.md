# v0.3 — AUR and PKGBUILD Review

Owner: Hung Vo · Size: L · Dates: set from prior release data

## Release Outcome

A user can statically review a local PKGBUILD, an AUR package, or the change between an
installed and candidate AUR revision without executing package-controlled code.

## In Scope

- Static analysis of `PKGBUILD`, `.SRCINFO`, `.install`, patches, and relevant repository
  metadata.
- Current metadata from the AUR RPC and source/build history from the package Git repo.
- Source URL, transport, checksum/signature, install-script, and obfuscation rules.
- Diff-first review of candidate AUR updates.
- Installed foreign-package inventory and links to available evidence.

## Non-Goals

- Executing `PKGBUILD`, `makepkg`, package functions, tests, or install scripts.
- Building packages or downloading/building upstream source archives by default.
- Claiming maintainer tenure or ownership-transfer history without authoritative data.
- Automatically blocking `yay`, `paru`, or pacman transactions.
- CVE coverage for arbitrary AUR packages.

## Milestones

### M1. Safe package target model

- Add `scan-pkgbuild <path>` and `scan-aur <package>` commands.
- Fetch AUR Git content with the same no-hooks/no-submodules/no-filters and resource-limit
  contract used by v0.2.
- Treat `.SRCINFO` as data and report when it disagrees with statically derived facts.
- Never source the PKGBUILD or run `makepkg --printsrcinfo`; both can execute package code.

Exit: adversarial PKGBUILDs cannot trigger shell execution, command substitution, source
downloads, or filesystem access through the scanner.

### M2. Shell-aware static analyzer

- Evaluate a shell parser that preserves source locations and tolerates Arch-specific
  PKGBUILD patterns.
- Model assignments/arrays and known package functions without evaluating general shell.
- Mark unresolved dynamic values and parser fallbacks as coverage limitations.
- Analyze `.install` script functions separately at higher sensitivity.

Exit: common Arch/AUR fixtures produce useful structured facts without evaluating shell.

### M3. Initial package rule catalog

- Flag plain HTTP sources, `SKIP` checksums, missing signatures where expected, dynamic
  download/execute chains, `eval`, encoded blobs, and suspicious shell construction.
- Detect network or host writes in `.install` functions and attempts to escape `$pkgdir`
  in packaging functions.
- Inventory `-bin` payload provenance and whether upstream verification is available.
- Separate normal build-time network/source declarations from runtime/install behavior.

Exit: every finding has evidence and high-noise rules are capability/informational items
rather than automatic high severity.

### M4. Metadata and history

- Use AUR RPC only for fields it actually exposes: current maintainer, votes/popularity,
  orphaned/out-of-date state, version, and timestamps.
- Use Git history for content/revision comparison, not as proof of maintainer ownership.
- Record source revision and retrieval time so metadata changes can be reproduced.

Exit: reports make the provenance and limitation of every metadata heuristic explicit.

### M5. Update review workflow

- Add `aur review <package>` to compare the installed/baselined revision with the current
  candidate.
- Highlight new sources, changed checksums, new install hooks, newly dynamic expressions,
  new binary files, and worsened scan coverage.
- Reuse v0.1 trust, acknowledge, history, and notification concepts.
- Provide copyable next steps for the user's AUR helper; do not run the upgrade in v0.3.

Exit: the user can review exactly what changed before separately invoking their helper.

### M6. UI and release

- Add an AUR tab to the existing panel without expanding the bar's default alert surface.
- Show foreign packages as inventory, not automatic warnings.
- Document unsupported PKGBUILD constructs and false-positive handling.

## Success Metrics

- Zero target-controlled shell/build execution across the adversarial fixture suite.
- 100% of dynamic/unresolved constructs receive a visible coverage limitation.
- Zero known high-severity false positives and zero untriaged high-severity results in the
  pinned package corpus used for release.
- Every changed source/checksum/install-script fixture is highlighted before helper advice.

## Test Matrix

- Official-style and real-world-shaped PKGBUILDs using arrays, functions, conditionals,
  architecture suffixes, variable expansion, and sourced helper files.
- Adversarial command substitutions, `eval`, encoded payloads, dynamic URLs, and nested
  shell constructs.
- `.install` scripts with service creation, network access, and writes outside package
  ownership expectations.
- Stale/missing `.SRCINFO`, orphaned packages, renamed packages, and unavailable AUR.
- Diff fixtures for checksum/source/install-script changes and history rewrites.

## Acceptance Criteria

- No target-controlled build or shell code executes during analysis.
- Dynamic/unresolved constructs appear as limitations, not clean results.
- AUR ownership history is never inferred from Git authors alone.
- Review output emphasizes changed behavior and provenance over popularity scores.
- The scanner remains useful for a local PKGBUILD with no network access.
