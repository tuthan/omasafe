# v0.2.5 — Coverage truth and opaque executable review

Status: implementation complete after the 2026-09-08 follow-up review.
External release gates remain environment-dependent.
Owner: Hung Vo · Size: L

## Release outcome

OmaSafe distinguishes file inventory, language recognition, syntax analysis,
behavior-model coverage, and execution exposure. Native code is reported as
opaque, high review risk without calling it malicious. Advisory policy allows
with a prominent review requirement. Hardened policy blocks a guarded enable or
review-update until every in-scope opaque native file has a current external
assessment and human acceptance bound to its exact SHA-256 and plugin identity.

This release is the coverage/reporting and binary-policy slice only. It does not
add Node.js or Ruby analyzers or materially expand Python/shell behavior analysis.
Those remain follow-on work justified by corpus evidence.

## Release disposition prerequisite

v0.2.4 is rolled forward into v0.2.5 and was not released separately. Its
pre-release implementation and stale evidence are not release evidence. A
complete v0.2.5 evidence set must be generated at the release candidate before
tagging:

1. Do not publish v0.2.4 separately; the version rolls forward here.
2. Generate one complete evidence set for the v0.2.5 release candidate.

Do not regenerate an intermediate evidence set merely to invalidate it with the
next policy identity. In either path, no release claim may cite the stale
`release-reports/provenance.json` revision as current evidence.

## Evidence motivating the release

The earlier omajelly scan was a non-gating design probe and is not promoted to
a v0.2.5 regression baseline. v0.2.5 relies on the independently authored
classification, coverage, policy, and report fixtures in the test matrix below;
no numeric corpus claim is part of this release.

Source inspection establishes the following current behavior:

- Native magic is classified before extension and shebang. Known extensions
  precede shebang classification.
- Shebang handling recognizes `/usr/bin/env ` through a narrow prefix removal,
  misses `/bin/env` and `env -S`, and does not recognize Node.js or Ruby.
- Bash, sh, zsh, dash, ksh, and ash currently share `PayloadKind::Shell` and the
  same modeled analysis. Fish falls back to an unsupported executable/text kind.
- Standalone JavaScript uses the lexical QML/JS scanner; it is not a Node.js API
  model.
- Python has parser-backed download/execute flow plus lexical/shared checks, but
  every Python limitation is currently attributed to
  `oma.python.download-execute`, including reverse-shell limitations.
- Native formats are changed to `CoverageState::Analyzed` after inventory and
  reference handling. The current unsupported-executable blocker selects only
  executable entries whose coverage state remains `Unsupported`.
- `executable_digest_approved` is the intended precision-independent policy seam,
  but every CLI caller currently passes `false` and the input is one global bool.
- QML `Process` observations prove process capability only. They do not prove the
  analyzer understands the launched helper or its behavior.

## Strategy decisions

| Decision | v0.2.5 choice |
| --- | --- |
| Release scope | Coverage correctness, language recognition, opaque-code inventory/review, policy wiring, migration, and consumer compatibility only |
| Binary risk language | `high-review-risk` / `opaque-behavior`; never a High malicious-behavior finding solely because a binary exists |
| Enforcement path | Precision-independent hardened blocker; no H8b blocking-family admission |
| Review state | New per-file `omasafe.executable-review.v1` binding using ADR-0003 identity/expiry/audit patterns; not a blanket override |
| External assessment | Manually recorded evidence from a scanner or qualified review in v0.2.5; no automatic upload or network lookup |
| Existing plugins | No automatic disable; report migration state immediately and enforce on the next guarded enable/review-update under hardened policy |
| Report schemas | Keep `omasafe.report.v1`, `omasafe.analysis.v1`, and `omasafe.review-summary.v1`; add bounded optional fields |
| Enforcement schema | Publish `omasafe.enforcement.v2` because blocker detail and per-file review authorization change materially |
| Catalog/severity | `RULE_CATALOG_VERSION` 9; `SEVERITY_TABLE_VERSION` remains 1 |
| Parser features | Add no grammar feature. Test all four existing qml/python projections and support only declared release profiles |
| Payload compatibility | Keep existing serialized `PayloadKind` and `Language` variants; add open, optional language/interpreter hints instead of breaking strict consumers |
| Dynamic reference | Narrow only proven in-tree constant `Qt.resolvedUrl` cases; retain unknown, traversal, symlink, remote-base, and variable cases |
| v0.4 relationship | Reuse corrected shell classification contracts; leave PKGBUILD parsing and Arch-specific semantics to v0.4 M2 |

## Scope

### C1 — Classification and coverage model · Size M

Add orthogonal fields instead of overloading `CoverageState`:

- inventory state: bytes/path metadata collected or incomplete;
- `language_hint`: open string plus confidence/source (`extension`, `shebang`,
  manifest, invocation, or unknown);
- syntax coverage: parser, lexical fallback, unsupported, unavailable, or bounded;
- behavior coverage by rule family;
- code exposure: entry point, known execute/load edge, possible/dynamic, explicitly
  unreferenced, or unknown;
- content class: native code, interpreted code, archive/container, bytecode/WASM,
  ordinary data, or unknown.

Correct shebang parsing for direct interpreter paths, `/usr/bin/env`, `/bin/env`,
and `env -S` without executing `env`. Recognize Node.js, Ruby, Perl, Lua, PHP,
PowerShell, fish, and TypeScript as language hints. Recognition is inventory
support only. Preserve extension/shebang conflicts as evidence rather than choosing
silently. A file invoked through an interpreter remains executable exposure even
when mode 0644; an unrelated unreferenced text file does not become a blocker solely
from its extension.

Replace `python_rule_ids` with typed reason-to-family attribution. The report must
distinguish the Python parser/flow limit from the line-oriented reverse-shell limit
and must not assign both to `oma.python.download-execute`.

Exit: named classification fixtures have deterministic state and coverage; no
recognized unsupported language is reported as behaviorally analyzed.

### C2 — Opaque native-code inventory · Size M

Inventory ELF, PE, Mach-O executables and shared libraries regardless of extension
or execute bit, including `.so`, `.node`, and native language extensions. Record:

- normalized relative path, file size, format, architecture when bounded parsing
  supports it, and exposure state;
- exact full-file SHA-256 with `exact|unavailable` state; never authorize from the
  existing sampled hash;
- source commit/tree/content identity where available;
- whether a known reference is execute, native load, ordinary read, or unresolved.

Use a bounded, pinned native-object parser only for format/header metadata. Symbols
and strings are optional context and never behavior proof. Malformed headers,
oversized files, budget exhaustion, packed content, archives, AppImages, WASM, and
bytecode remain typed opaque/unknown states. Do not recursively unpack by default.

No scanner runs `ldd`, target `--version`, a loader, decompiler plugin, package
manager, build, test, hook, submodule, or target-controlled command.

Exit: inventory completion cannot set behavioral coverage to complete or clear the
opaque-code policy condition.

### C3 — Executable review evidence and policy · Size L

Add `ExecutableReviewBinding` under schema `omasafe.executable-review.v1` with:

- plugin ID, normalized path, native format, exact SHA-256;
- source commit/tree/content digest and review-policy version;
- assessment method enum (`local-malware-scan`, `remote-hash-reputation`,
  `manual-binary-review`, `reproducible-build-review`, or `signature-review`);
- assessor/tool/provider and version where known;
- assessment outcome (`no-known-issue`, `issue-found`, or `inconclusive`), performed
  time, bounded report reference or report digest, and limitations;
- operator decision (`accepted` or `rejected`), human-authored reason, decision time,
  expiry, and audit event ID.

The CLI records metadata, not raw external reports or binary contents. A no-detection
scanner result, checksum, signature, marketplace claim, matching source tree, or
reproducible-build claim is supporting evidence, not proof of harmless behavior.
Hardened authorization requires assessment outcome `no-known-issue`, operator decision
`accepted`, a live human confirmation, and an exact binding match. An assessment never
authorizes by itself. `issue-found`, `inconclusive`, operator-rejected, expired,
malformed, or mismatched records never authorize through this mechanism; the existing
exceptional override path remains separate and retains every blocker.

Replace the global `executable_digest_approved: bool` evaluation input with typed
opaque-code items and the exact set of matching review bindings. Each decision keeps
the path/digest-specific blocker details. Acceptance clears only its matching
`opaque-executable-unreviewed` item; unrelated findings, coverage loss, stale
identity, and postcondition blockers remain.

Reuse [ADR-0003](../adr/0003-enforcement-staging.md)'s read → exact preview →
confirmation → identity re-read → one mutation → structured readback transaction.
Do not encode executable review as an existing blanket `OverrideBinding`. Existing
overrides remain available for their documented exceptional purpose.

Opaque native code is handled as follows:

| Situation | Advisory | Hardened guarded lifecycle |
| --- | --- | --- |
| Native code, exposure known or unknown, no matching review | Allow with high review-risk item | Block with path/digest-specific `opaque-executable-unreviewed` |
| Bytecode/WASM or archive/container/AppImage, including malformed or packed content | Allow with typed opaque review-risk item | Block pending the same exact accepted review binding; never claim behavioral analysis |
| Every in-scope opaque file has a matching `no-known-issue` assessment and accepted operator decision | Allow and retain evidence | Allow this blocker only; retain all other blockers |
| Review rejected, inconclusive, expired, or identity changed | Allow with prominent unresolved state | Block |
| Unsupported text script with a known interpreter/entry edge | Allow with high review-risk item | Block pending matching review |
| Unreferenced unsupported text/data with no execution evidence | Inventory/coverage notice | No opaque-executable block solely from extension |
| Image, font, media, or other ordinary data | Inventory context | No opaque-code block |
| Runtime download followed by execute/load | Existing behavior finding plus unavailable future-byte review | Apply only existing admitted policy; no preapproval of unknown bytes |

This is a precision-independent policy requirement. It does not add a finding family
to H8b and does not change any finding to High severity.

Exit: a reviewed digest cannot authorize another path, plugin, revision, or changed
file; one accepted item cannot clear another blocker.

### C4 — CLI, report, and bounded presentation · Size M

Add read-only report fields for coverage summaries, code exposure, opaque review
state, and exact omission arithmetic. Keep payload rows omitted from the review
profile by design. Add commands following existing plugin-state conventions:

```text
plugins executable-review list ID --format json
plugins executable-review add ID --path PATH --sha256 DIGEST \
  --method METHOD --assessment-outcome OUTCOME --decision DECISION \
  --performed-at TIME --expires TIME \
  --provider PROVIDER --report-ref REF --reason REASON \
  --expected-head COMMIT --expected-tree TREE --expected-digest DIGEST --yes
plugins executable-review revoke ID --path PATH --sha256 DIGEST --reason REASON --yes
```

`add` and `revoke` are interactive state mutations. Exact preview and current-turn
confirmation are required before `--yes`; the expected identity fields are mandatory
when available. v0.2.5 records reviews only for the currently installed tree
after exact identity revalidation. Candidate review records bound to an exact
remote source revision without installing it are deferred; no command uploads
a file, contacts a reputation service, or executes an external scanner in
v0.2.5.

Bounds, applied before model/UI transport:

- existing raw-stream caps and the 1,572,864-byte review-profile cap remain;
- review profile emits at most 128 code-exposure rows and preserves totals/omissions;
- normalized path ≤512 UTF-8 bytes; provider/tool ≤128; report reference ≤512;
- reason ≤1,024; each limitation ≤256 with at most 16 retained;
- no raw scanner output, certificate, symbol table, binary string dump, or secret
  value enters report/state history.

Exit: full/review/summary reports conserve totals, remain within bounds, redact
source-derived strings, and preserve analysis and enforcement identity semantics.

### C5 — Dynamic-reference precision · Size S

Treat `Qt.resolvedUrl("literal-relative-path")` as a proven in-tree reference only
when the call has a constant literal, the base is the current inventoried source,
normalization contains no traversal/scheme/absolute path, the target is an
inventoried regular file, and no symlink is crossed. In that case retain the
invocation/load edge and omit the dynamic-reference finding.

Variable arguments, concatenation, remote or file schemes, unknown bases, missing
targets, traversal, directories, and symlinks retain the current finding/coverage
behavior. Increment the affected rule review revision and semantic digest.

Exit: known omajelly-shaped and existing corpus false-positive fixtures clear while
true computed-path fixtures remain detected.

### C6 — Feature profiles and sibling consumer · Size M

Before introducing any new grammar, run and gate all four existing analyzer
projections:

1. `qml-python` (release/default CLI);
2. `qml-only` focused compatibility check;
3. `python-only` focused compatibility check;
4. `lexical-only` constrained build.

Each projection must compile, test, publish a matching reviewed compatibility
declaration, and report parser absence accurately. Update `release-gate.sh` so the
two focused single-parser checks cannot be skipped. Future language grammars should
not become independently supported feature switches by default; a later plan must
choose a bounded release-profile matrix.

Provide frozen producer fixtures and a compatibility note to the sibling plugin and
agent report consumer. Older reports render the legacy view. New optional coverage
fields map unknown enum/string values to explicit unknown state. Record the sibling
commit/version or retain legacy UI claims in release notes.

Exit: no supported build profile silently loses a parser or claims complete behavior;
new CLI reports remain safe in old consumers.

## Identity, schema, cache, and migration contract

- Keep outer `omasafe.report.v1`, `omasafe.analysis.v1`, and
  `omasafe.review-summary.v1`. New analysis/report fields are optional and bounded;
  impossible counts or malformed required identity remain errors.
- Publish `omasafe.enforcement.v2` with typed blocker items and authorization detail.
  v1 decisions remain readable history but cannot be interpreted as binary-review
  authorization.
- Publish `omasafe.executable-review.v1`. Its `review_policy_version` changes only
  when evidence acceptance semantics change; unrelated analyzer prose does not
  invalidate exact binary evidence.
- Set `RULE_CATALOG_VERSION` to 9. Keep `SEVERITY_TABLE_VERSION` at 1. Update the
  detector/catalog/limits fingerprints and the dynamic-reference rule review revision.
- Policy behavior changes rotate enforcement identity. Existing v1 overrides bound
  to the old enforcement identity become invalid for v2 decisions and remain visible
  as historical records. The CLI must preview re-creation; it never migrates an
  override silently.
- Invalidate pre-v0.2.5 analysis caches for current-policy reuse. Old reports remain
  readable with stale/legacy coverage. Source identity does not change merely because
  analyzer or enforcement policy changes.
- Avoid adding serialized `PayloadKind`/`Language` variants in this release. Open
  optional language hints prevent strict out-of-tree consumers from failing on a new
  closed enum.

Migration behavior:

- Advisory installations immediately show opaque-code high review-risk items and
  continue to allow lifecycle operations.
- Hardened existing installations receive a preflight `would-block` status for the
  next enable/update. OmaSafe does not disable a currently running plugin.
- The next guarded hardened enable/review-update blocks until exact accepted review
  bindings exist. Native Omarchy lifecycle bypasses remain disclosed.
- Changed path, file digest, plugin/source identity, expiry, operator rejection, or
  review-policy version invalidates only the affected executable review.

## Security and compatibility test matrix

- ELF/PE/Mach-O renamed with script extensions; malformed/short headers; shared
  libraries and addons without execute bits; ordinary NUL-bearing data.
- Exact digest available/unavailable, oversized/budget-limited content, changed bytes,
  changed path, copied binary across plugins, and multiple binaries with only one review.
- Known execute/load edge, ordinary read edge, dynamic reference, unreferenced native
  file, and interpreter invocation of a mode-0644 unsupported script.
- Direct shebang, `/usr/bin/env`, `/bin/env`, `env -S`, conflicting extension/shebang,
  extensionless launchers, and fish/zsh/ksh/dash/ash coverage labels.
- No-known-issue/issue-found/inconclusive/expired external assessment; accepted/rejected
  operator decision; malformed provider data;
  assessment reference containing hostile text; no scanner output or secret retention.
- Advisory allow, hardened block, exact accepted allow, unrelated blocker retention,
  old override invalidation, no automatic disable, and native lifecycle bypass disclosure.
- All four current parser feature projections, missing parser, compatibility declaration
  mismatch, stale cache, legacy report/decision, old sibling, and new sibling.
- Proven in-tree constant resolvedUrl; variable, concatenated, traversal, absolute,
  scheme, missing, directory, and symlink controls.
- Full/review omission arithmetic, collection flooding, deterministic ordering,
  bounded JSON escaping/redaction, interrupted scan, and unavailable file content.

## Success metrics

- 100% correct classification and policy outcome for every named positive/benign
  fixture in the test matrix; zero target-controlled execution.
- All four existing parser projections pass tests and have a valid compatibility
  declaration. Release/default and lexical-only remain the documented product profiles.
- Every native-format fixture receives exact opaque-code inventory or an explicit
  digest/format limitation; none is reported as behaviorally complete.
- Every hardened opaque-code block names the affected path and digest state; a matching
  accepted record clears only that item.
- Zero known High-severity false positives. No new H8b family is admitted and no new
  precision/recall claim is published in v0.2.5.
- Triage every new or changed finding produced by the pinned release sample. Report
  sample size, current-policy dispositions, unresolved cases, and per-family results;
  do not combine them into an overall safety percentage.
- All report collections conserve `total = emitted + omitted` and fit existing stream,
  review-profile, and runner summary bounds.

## Risks

| Risk | Control |
| --- | --- |
| Opaque code is presented as malicious | Separate high review risk, behavior findings, coverage, and policy reasons in schemas and UI |
| External scanner result becomes a safety verdict | Require human acceptance, retain method/result/limits, and never let it clear unrelated blockers |
| Binary review state becomes a blanket bypass | Per-file exact binding and typed blocker matching; existing override remains separate |
| Policy update unexpectedly disrupts hardened users | Preflight migration status, no automatic disable, release notes, exact lifecycle preview |
| Execute-bit checks miss loaders/interpreters | Model execute/load/interpreter exposure independently from file mode |
| Native metadata parser adds attack surface | Pinned bounded parser, malformed fixtures, no execution or recursive unpacking |
| New language hints imply analysis | Separate language recognition from syntax/behavior coverage and use explicit unknowns |
| Feature combinations explode | No new grammar feature; gate current four projections and require future bounded-profile decisions |
| Report growth breaks sibling/agent consumers | Optional bounded fields, frozen fixtures, G4 handoff, exact omission arithmetic |
| v0.2.5 preempts PKGBUILD work | Keep Arch build semantics out of scope and carry only shared classification contracts into v0.4 |

## Explicit non-goals

- Node.js, Ruby, Perl, Lua, PHP, PowerShell, TypeScript, fish, or new Python/shell
  behavior analyzers.
- Native-binary behavior semantics, disassembly, decompilation, malware verdicts,
  vulnerability identification, sandboxing, or proof of reproducible builds.
- Automatic VirusTotal/hosted reputation lookup, binary upload, scanner installation,
  API-key handling, or network submission. These remain separately reviewed backlog.
- Recursive archive/AppImage extraction, dependency installation, package builds,
  target tests, hooks, submodules, LFS filters, or target execution.
- New H8b blocking-family admission, severity-table change, automatic trust, automatic
  review acceptance, automatic disabling, or native lifecycle interposition.
- Cross-file/interprocedural language flow expansion or PKGBUILD/Arch shell semantics.

## Deferred follow-ons

Deeper Python/shell modeling is the first candidate after v0.2.5, including native
API models, multiline Python flow, interpreter bridges, and dialect-specific coverage.
Node.js analysis requires corpus demand, an owner, a bounded parser-profile decision,
and its own plan for CommonJS/ESM, child processes, filesystem/network APIs, native
addons, and package lifecycle scripts. Ruby remains unscheduled until corpus evidence
and a concrete threat model justify a dedicated adapter. Candidate executable-review
records for an uninstalled remote revision also remain follow-on work. No future
version number is reserved by this plan.

## Acceptance criteria

C1–C6 and G0–G5 meet their stated exits. The version/catalog/severity/schema choices,
ADR, generated assets, CLI help/man/completions, frozen fixtures, cache behavior,
consumer compatibility, release notes, and package version agree. Hardened opaque-code
policy uses the precision-independent path and preserves H8b's empty family set.

Any deferred required behavior must be removed from v0.2.5 release claims rather than
hidden behind a generic partial label. Unknown and unsupported states remain visible.
The release cannot claim binary safety, complete language analysis, external scanner
endorsement, or protection from native Omarchy lifecycle bypasses.
