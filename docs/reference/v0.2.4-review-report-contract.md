# v0.2.4 review report contract

Status: **implemented producer contract, 2026-09-07; not emitted by v0.2.3**.
Owner: Hung Vo. G0 review target: 2026-09-07. G2 freeze commit/date: pending
producer fixture verification. See the [implementation plan](../plans/v0.2.4-rule-detection-clarity.md).
This document resolves the initial draft's open schema, identity, byte-budget,
and selection decisions, including the second-round identity and legacy-cache
corrections. A changed type/meaning requires updating this document,
producer fixtures, and the recorded freeze together.

## Scope and compatibility

`omasafe.report.v1` and `omasafe.analysis.v1` remain unchanged. Existing required
fields retain their types and meanings. The additions apply to `scan-plugin`
and `plugins analyze`; rule-support projections apply to existing `rules`
commands. `scan` snapshots remain aggregate reports under their existing schemas.

New producers emit the fields specified below. Rust readers use optional fields
with `serde(default)`; legacy reports may omit them. Unknown enum strings map to
an explicit unknown state in consumers, not a failed deserialization or a clean
result. Required existing schema/identity validation remains strict. Do not apply
this tolerant rule to malformed numeric counts or impossible omission arithmetic.

No array index, finding prefix, or order of JSON object members is a persistent
identifier. Summary enums describe observations, not policy authorization.

## Identity and internal evidence

`analysis.policy_identity.detector_logic_fingerprint` is an optional 64-character
lowercase SHA-256 hex string. New producers always supply it; legacy missing/null
is not comparable to the current detector. The source hash construction and
cache behavior are defined in the plan.

Define `policy_identity_digest = SHA256(canonical_json(complete PolicyIdentity))`.
This is full producer/cache provenance, not the cross-build review compatibility
key. New policies also include `rule_semantics_catalog_digest` and nullable
`review_compatibility_declaration_id` from the plan. Canonical JSON uses recursively
sorted object keys, original array order, UTF-8,
and no insignificant whitespace. Use one implementation for CLI and corpus
consumers and golden cross-language test vectors; never hash pretty JSON in one
consumer and compact JSON in another.

Define `rule_semantic_identity_digest = SHA256(canonical_json(RuleSemanticIdentity))`.
The per-rule payload and reviewed compatibility declarations are specified in the
plan. Do not derive this by deleting one field from `PolicyIdentity`: package
version and prose/catalog-release fingerprints are excluded too. New `rules explain`
output includes the canonical semantic object and digest so independent corpus
consumers can verify projection and feature/limit dependencies.

Define `occurrence_id = SHA256("omasafe.occurrence.v1\0" || canonical_json(R))`,
where R has `rule_id`, canonical `relative_path`, `line`, `column`, and original
normalized `semantic_value`. Missing locations serialize as null. Confidence and
analysis method describe the assessment, not the occurrence key. This identifies
the existing normalized occurrence at its location, not raw source bytes or a
location-independent behavior across edits. Compute before suppression, redaction,
and presentation shortening. Exclude prose, timestamps, profile, and step retention.

Removing confidence here does not remove it from the existing analysis fingerprint,
and does not grant automatic reuse after an attribution correction. A predicate
or evidence-method/confidence change increments the affected rule's review revision.
Thus the occurrence can retain its ID while its old triage label requires review.
Cosmetic rebuilds retain the compatibility key only with valid declarations; an
undeclared build cannot borrow cross-build labels or suppressions.

Attach bounded evidence observations to `ResultParts` and transfer them through
normalization to `AnalysisArtifacts`, keyed by the normalized occurrence. Avoid
parallel vectors whose ordering could associate one finding with another path.
Two detectors producing the same normalized occurrence merge/deduplicate their
observations using typed location/role/method keys; render one finding as today.

An observation ID is a SHA-256 over occurrence ID plus typed role, canonical
location, and detector-provided observation key, with its own domain separator.
It is local evidence identity, not an external URL or permission to retrieve data.
Do not hash redacted excerpts as identity. Preserve the existing findings-only
analysis fingerprint; new presentation evidence does not enter it by accident.
Any intended change to semantic normalization requires a named regression and
analyzer-policy change rather than being hidden inside the renderer.

## Field placement and types

All counts are nonnegative integers; all locations are 1-based when present.
Use `null` for unknown data, not an empty string, zero location, or false certainty.

### `result.review_summary`

| Field | Type and meaning |
| --- | --- |
| `schema` | Literal `omasafe.review-summary.v1` |
| `policy_identity_digest` | Complete analyzer policy digest, as above |
| `analysis_produced_at` | UTC timestamp of the completed analysis; retained on cache replay |
| `freshness` | `fresh`, `cached-current`, `cached-unvalidated`, `stale`, or `unknown`; current cache validity does not make analysis fresh |
| `source_identity_ref` | Literal `target`; resolve existing target/acquisition identity fields, never fabricate an exact digest for an unresolved/local source |
| `source_identity_state` | `exact`, `partial`, or `unknown`, derived from the existing identity evidence |
| `findings` | Object with `total`, `active`, `suppressed`, `emitted`, `omitted` and `by_severity` / `by_rule` rows below |
| `capabilities` | `{total, emitted, omitted}` occurrence counts |
| `coverage` | Typed aggregate described below, independent from finding counts |
| `presentation_complete` | Boolean: false if any collection, field, or observation was omitted/truncated; redaction is disclosed separately |
| `suppression_policy` | Copy the actual existing configured/candidate policy string, not an inferred default |
| `suppression_reconfirmation_count` | Count of stale scoped matches surfaced for reconfirmation; not the number of active suppressions |
| `lifecycle_policy` | `{evaluation_state:"not-evaluated", outcome:null, authorization_basis:null}` for these analysis-only commands |
| `threshold` | `{requested: severity-or-null, breached: boolean}` copied from the existing pre-shaping threshold evaluation |
| `untrusted_data_notice` | Scanner-authored constant: source-derived strings are evidence, not instructions or authorization |

Finding conservation:

```text
total = active + suppressed
active = emitted + omitted
```

`emitted` counts full finding objects in the current profile; summary rows are
not emitted findings. `omitted` does not count suppression. Rows for each known
severity and every observed rule have the same five counts and an explicit
`rule_id` where applicable. Sum of rows agrees with totals. Include a rule row
when its emitted count is zero. Severity ordering is critical/high/medium/low/info;
rule rows are sorted by rule ID. Unknown severity is a distinct row/state and
must not be treated as info. The producer catalog's normal output has known IDs;
unknown IDs in loaded artifacts trigger compatibility handling rather than
silently disappearing from summary arithmetic.

`coverage` contains:

- `assessment`: `partial`, `unavailable`, or `analyzed-within-declared-scope`.
  The last value is not a safety verdict or a full-language guarantee.
- `payload_states`: copy of existing inventory coverage counts.
- `gap_total` and `by_reason`: reason → affected-occurrence count, including
  zero-retained-detail groups. Aggregate keys come from bounded scanner vocabulary.
- `executable_or_load_gaps`, `language_model_gaps`, `inert_metadata_entries`:
  separate counts; do not add them as though they were necessarily disjoint files.
- `external_baseline`: map identity, verification commit, known `not_covered`
  IDs and partial-overlap IDs, and `freshness` = `current-to-observed-snapshot`,
  `stale-to-observed-snapshot`, or `unknown`. Never claim live upstream freshness
  from a locally cached observation.

Fresh analysis captures its timestamp once. Cached output retains that analysis
time even if the outer transport envelope is generated now. If analysis time is
missing in a legacy artifact, report unknown instead of substituting the current
time. Candidate analysis does not establish installation or enforcement status.

### Additions to each `analysis.findings[]`

| Field | Type and meaning |
| --- | --- |
| `occurrence_id` | Digest of the normalized location/value occurrence, excluding confidence/method |
| `rule_semantic_identity_digest` | Compatibility digest for this rule's declared predicate/evidence meaning; not a full cache identity |
| `analysis_method` | `ast-dataflow`, `ast-syntax`, `shell-ir-flow`, `lexical-correlation`, `lexical-pattern`, or `inventory-reference`; absent legacy value is unknown |
| `evidence_steps` | Array of `EvidenceStep`, bounded below; an empty array is allowed for a legacy detector without structured evidence |
| `evidence_summary` | `{total, emitted, omitted, observation_collection_complete}`; observed-step counts, never a claim that the behavior graph is complete |
| `behavior_context` | Object with typed source/sink/connection/trigger/destination fields below; null if no structured context is supported |
| `presentation` | `{redacted, truncated, redaction_classes, omitted_fields}`; scanner-authored bounded metadata |
| `display_relative_path` | Escaped display version of the canonical location; consumers must use this or their own equivalent literal renderer |

`EvidenceStep` fields: `id`, `role`, `relative_path`, `display_relative_path`,
`line`, `column`, `analysis_method`, `detail`, `origin`, `redacted`, `truncated`.
Roles: `source`, `assignment`, `sink`, `trigger`, `observation`, `barrier`.
`origin` is `source-derived` or `scanner-derived`. Detail is bounded literal text;
it is never a rendered hyperlink, shell command action, or rich-text document.
Locations without exact columns use null. No fabricated step may fill a missing
source, trigger, or sink merely to make a chain look complete.

`behavior_context` fields:

- `connection`: `connected`, `indicator`, or `unresolved`. Connected means the
  supported static model established the link, not that it executed.
- `source_class`: `network-bytes`, `sensitive-local-data`, `static-local-file`,
  `user-input`, or `unknown`.
- `sink_kind`: `python-code`, `shell-code`, `process-argv`, `network-send`,
  `input-injection`, `screen-capture`, `persistence-write`, `file-write`, or `unknown`.
- `sink_argument_role`: a scanner-authored identifier such as `exec-arg0`,
  `interpreter-script-file`, `interpreter-code-string`, `request-body`, or `unknown`.
- `trigger`: `interactive`, `background`, or `unknown`; location evidence is required
  for a known value. A function body without caller analysis has an unknown trigger.
- `destination`: null or `{scheme, host, port, path_display, dynamic, redacted}`.
  Preserve known parts of a partially dynamic destination and mark unknown parts
  null; no DNS lookup or trust classification is performed.

Keep legacy `confidence` strings. A syntax-backed predicate can be `ast-backed`;
H5/H6 line correlation is always `lexical-fallback`, regardless of the file's
parser metadata. AST syntax is a method, not a numeric confidence in maliciousness.

### Other additive analysis fields

`analysis.parsers`: object keyed by language, each value containing `method`,
`grammar`, `grammar_version`, and `runtime_version` (nullable). Record actual
build features. The existing `analysis.parser` stays QML-specific.

`analysis.coverage_gaps[]`: `{reason, language, rule_ids, relative_path, line,
impact, detail}`. `impact` is `executable-or-load`, `language-model`, or
`metadata-only`. `rule_ids` lists affected known rules where that can be determined;
empty means broader coverage. One record is a deduplicated
(reason/language/path/line/impact/rule set) observation. Preserve precise counts
before retaining only a bounded subset. Existing limitation strings remain for
compatibility; do not double count the same gap when merging both sources.

Build typed records at the point a gap is known where practical. For existing
strings, use an explicit mapping table and an `unclassified` reason for unknown
legacy values. Do not guess a path/rule by splitting arbitrary plugin text.
Known inventory states add partial-language and executable/load gaps even when
the old limitation list is empty. Presentation omissions never become executable
coverage gaps. Already-existing compatibility omission strings may remain until
consumers migrate; route them to presentation omission accounting and exclude
them from `coverage_gaps` and analysis-gap counts.

`result.report_profile`: keep existing fields and omission entries; add
`selection_strategy` = `canonical-full-v1` or
`severity-family-file-round-robin-v1`, and `presentation_version` = 1.
Also emit `redaction_policy_version` = 1 after the full presentation transform.
The private v2 cache validates both versions; a missing marker is a cache miss,
not evidence that an old report was redacted. Emit these markers for full and
review profiles, including installed analysis that previously omitted profile
metadata. Readable legacy reports may lack them and remain explicitly legacy.
Extend `omissions` for `coverage_gaps`, suppression-applied/reconfirmation details,
and evidence observations/shortened fields. Each collection entry retains
`{total, emitted, omitted}`. Field shortening uses separate field/byte counters,
not a fictitious omitted finding count. Full output can still have per-field
limits; “full” is not a promise of unbounded evidence.

### Rule help and coverage projection

`rules explain` adds `rule_support`: `{status, result_roles, predicates,
languages, methods, limitations, benign_examples, fixture_ids}`.
`status` is `implemented`, `partial`, or `planned`; capabilities and suspicious
predicates may have different supported scopes described in `predicates`.
Keep the existing `rule` object and external equivalences. Also provide
`rule_semantic_identity` and its digest as separate fields; these exclude prose
and expose the actual method/feature/limit dependencies.

Add a separate `blocking_admission`: `{admitted, enforcement_policy_identity,
evidence_reference}`. It describes the catalog family under the named policy,
not an evaluation of the scanned plugin. In v0.2.4 admitted remains false for
every rule family. `rules list` may include the same support objects; `rules
coverage` adds local support rows without replacing its external baseline map.

## Evidence caps and memory accounting

The existing review ceiling remains **1,572,864 UTF-8 bytes** for the actual
pretty-serialized envelope including its final newline. Capture envelope timestamp
once; use identical serialization for measurement and output.

| Bound | Full | Review |
| --- | ---: | ---: |
| Evidence observations per finding | 8 | 3 |
| Detail bytes per evidence step, after display transformation | 256 | 96 |
| New structured evidence/context block per finding, serialized | 8 KiB | 2 KiB |
| Legacy evidence string, displayed UTF-8 bytes | Existing 16 KiB | 512 |
| Findings/capabilities/invocation edges per collection | Existing complete bounded analysis | At most 1,024 each |
| Typed coverage detail records | 256 | 64 |
| Suppression applied/reconfirmation detail records per list | 256 | 64 |

Locations and metadata contribute to the serialized block cap. If locations are
too large, omit optional step details or whole steps with counts; do not falsify a
canonical path to make it fit. Fixed summary totals, rule rows, identity, unknown
states, and the reason-count map are mandatory. If mandatory existing envelope
fields plus this summary cannot fit, return error 1 with a bounded diagnostic;
do not emit a successful report missing its identity or completeness facts.

Limit internal observation retention to 8 per normalized occurrence and 4 MiB of
new observation storage per analysis, excluding the existing normalized semantic
results. Maintain total-observed counters with checked arithmetic; cap collection
work using existing node/statement limits. Exhaustion sets
`observation_collection_complete=false` with a reason count; it must not stop
finding detection. These are presentation evidence bounds, not a flow predicate.
Do not add them to the findings fingerprint. If a chosen implementation instead
lets a cap change detection or analysis coverage, that limit belongs in policy
and must be reviewed as a semantic change.

Selection of observation details preserves source and sink first, then trigger,
then earliest ordered intermediate assignments/observations within the cap.
Emit retained steps in source-location order with role/ID tie-breaks. If only a
single observation exists, preserve it without inventing a source/sink pair.
Total/omitted counts expose all retention losses, including upstream collection
loss versus display loss. A claimed connection can remain valid with shortened
explanatory evidence; mark the explanation incomplete and direct manual inspection
to the retained locations.

The private detailed cache keeps its current 2 MiB bound. A correct full result
too large to cache remains a valid live report and is not persisted; expose
`analysis_cache_persistence={state:"not-persisted",reason:"size-limit"}`. Never
store a shortened review subset as though it were complete cached analysis.

## Deterministic review selection algorithm

Replace the current blanket `truncate(1024)` and repeated tail-halving for findings.
Keep full normalized results and canonical full ordering unchanged.

1. Derive complete suppression-aware totals, severity/rule rows, gap counts,
   fingerprint, and threshold outcome. Build a minimal envelope with mandatory
   old fields and summary; variable detail arrays start empty. Measure it first.
2. Pre-render/redact candidate findings and apply per-finding evidence caps. Build
   severity bands in descending order. Within each band group by rule ID, then
   canonical path; sort each path queue by line/column, normalized semantic key,
   and occurrence ID (null location sorts before known location).
3. Visit rule IDs lexicographically, one candidate per rule per round. Within
   each rule cycle nonempty path queues lexicographically, taking one occurrence
   per path visit. Repeat until the band is exhausted. This is the priority stream;
   it is independent of absolute checkout paths, hash-map iteration, or time.
4. Admit priority candidates while under 1,024 findings and the envelope byte
   ceiling. Budget accounting includes updated count digits and JSON punctuation.
   If a candidate is too large, retry with source/sink-only evidence, then no
   structured steps and an 80-byte legacy excerpt; record all omissions. If its
   mandatory finding fields still cannot fit, omit it and continue testing other
   candidates in the same band. Do not admit lower severity while higher-severity
   findings remain omitted for size/count. Every omitted family stays in summary.
5. Sort the admitted subset back into the existing canonical rendered order:
   severity descending, path/rule/line/evidence, with occurrence ID as final tie-break.
   This deliberately is not a full-array prefix. Metadata declares the strategy.
6. Spend remaining space, in order, on coverage details, suppression reconfirmation
   details, suppression-applied details, capabilities, then invocation edges.
   Use deterministic canonical order within each collection and their count caps.
   Review inventory entries remain omitted as in v0.2.3. Summaries are never dropped.
7. Recompute all counters and serialize the complete envelope, including newline.
   If actual bytes exceed the ceiling despite the accountant, run bounded recovery:
   discard optional context detail arrays first, then repeatedly halve the retained
   finding priority stream from its lowest-priority end (1 becomes 0). Re-sort the
   retained set canonically and update all omissions on each attempt. Use actual
   serialization, not the suspect estimator, to validate each retry. With <=1,024
   findings this takes at most 12 retries after the initial failure, including the
   context-only drop and final mandatory-only attempt. Never re-admit candidates.
8. On successful recovery retain the scan's original threshold/exit outcome and
   add `report_profile.sizing_recovery={applied:true, reason:"accountant-mismatch",
   retries:N}`. Mark presentation incomplete. Emit a bounded scanner-authored warning
   on stderr; do not mix it into JSON stdout or classify it as analysis coverage loss.
   If the mandatory envelope still does not fit, or serialization itself fails,
   return error 1 with a bounded diagnostic. Never emit oversized or misleadingly
   complete success. Healthy reports use `applied:false`, null reason, zero retries.

Implement an exact byte accountant for rendered items/array delimiters and the
small mutable summary, rather than serializing a 1.5 MiB growing report for every
candidate. Actual serialization is authoritative. Unit tests compare the accountant with
the serializer on escaped Unicode/long count boundaries and inject underestimates
to exercise recovery. Unexpected recovery in normal release/corpus/contract fixtures
fails the release check: runtime resilience must not hide a sizing defect.

This guarantees deterministic output for the same completed artifacts/profile,
and prioritizes family/file diversity. It does not guarantee a detailed example
for every family when mandatory records or tiny remaining space make that
impossible. It guarantees complete family/severity counts or an explicit command
failure. No monotonic-prefix assumption across profile changes is supported.

## Presentation and untrusted-data boundary

Transformation order: normalize/identify → count and apply configured suppression
→ construct typed observations → redact → escape/cap → select → serialize/cache.
Preserve immutable internal results separately from display values. Apply the same
redaction to full and review profiles; no raw-secret profile is introduced.

Scanner explanations, counts, rule IDs, and policy results are scanner-authored.
Plugin excerpts, descriptions, paths, URLs, and values are source-derived even if
they appear inside a trusted tool's JSON envelope. Indicate this in step `origin`
and the summary notice. It remains the consumer's responsibility to treat these
as data: labels and keyword scanning do not themselves enforce an AI boundary.

- Text rows escape C0/C1 controls including tabs/newlines/carriage returns,
  U+2028/U+2029, U+202A–U+202E, U+2066–U+2069, and directional marks. Render
  visible escapes without breaking UTF-8; never render ANSI or rich text.
- JSON keeps canonical location strings for machine lookup in existing path
  fields, with JSON escaping for controls/bidi characters. Add escaped display
  paths and use them in UI/text. A decoded canonical path remains untrusted;
  never feed it directly into rich text, a shell, or an automatic file action.
- Redact URL userinfo, query values, fragments, authorization/proxy-authorization
  header values, cookie/set-cookie values, and explicit token/password/secret/API
  key assignment values in supported evidence text. Match field names
  case-insensitively; do not require a secret to meet an entropy threshold.
- For known URL contexts, preserve scheme/host/port and a bounded path display;
  replace known credential-bearing path segments. Redact all query values rather
  than attempting to enumerate secret parameter names. For malformed URL contexts,
  retain an opaque redacted value rather than revealing the original tail.
- Generic arbitrary plugin strings/paths cannot be guaranteed secret-free. Do not
  run URL interpretation over canonical filesystem location fields. The known
  redaction classes above are a bounded support contract, not comprehensive DLP.
  Unknown transformed/encoded secrets remain an explicit limitation.
- Never fetch, follow, preview remotely, execute, install, trust, or suppress based
  on evidence. A source URL is a review observation, not an enrichment request.
- Truncation after redaction must not cut halfway through an escape or UTF-8 code
  point. Track redaction classes and field truncations without retaining secret
  values in diagnostic errors or cache metadata.

### Legacy scan-snapshot output is also a presentation boundary

Keep the on-disk `omasafe.scan-snapshot.v1` schema and six context components.
Read and validate the original bounded snapshot first, then apply the current
presentation transform to a display copy on every output path, irrespective of
producer version, cached-valid/stale state, or whether validation was requested.
Never modify stored snapshot bytes, alert keys, generation, identity digests, or
counts while displaying history. Old data is not safe merely because it is cached.

`scan-cache show --format json` currently returns both `alerts` and nested
`snapshot.alerts`. Transform both, as well as source-derived messages/limitations
elsewhere in the returned object; sanitizing just the visible top-level projection
would leave credentials available to the AI in the nested copy. Apply equivalent
handling to live `scan` and notification message output. Current text cache display
does not list every alert; do not introduce that behavior just to test redaction.
Test existing text fields and the full JSON hydration route separately.

Add optional output-level presentation metadata naming the redaction policy and
truncation/redaction counts. A marker is informational, not permission to skip the
transform on a read. Raw canonical filesystem locations and identities keep their
machine meanings; message/excerpt display copies follow the redaction/escape rules.
Make repeated presentation stable (no growing backslash escapes); tests must cover
already-redacted new snapshots as well as raw v0.2.3 alerts. Enforce existing
string/output bounds after escaping and disclose any additional display loss.

Persist-time transformation of new detailed reports remains defense in depth.
Render-time handling of all snapshot generations closes the old hydration path;
neither requires a destructive migration of cached history.
