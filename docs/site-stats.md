# Landing-page supply-chain figures

The "Why" band of [`site/index.html`](../site/index.html) shows six numbers across
two sources. Both sources are mutable and regenerated continuously upstream, so
every number is credited to a snapshot date on the page and is treated as a
point-in-time observation, never a timeless fact.

Regenerate them with [`scripts/site-stats.sh`](../scripts/site-stats.sh), then copy
the values into `site/index.html` and move the snapshot dates with them.

```sh
scripts/site-stats.sh
```

## Sources

| Source | URL | Notes |
|--------|-----|-------|
| Omarchy plugin catalog | `https://plugins.omarchy.org/catalog.json` | The site is a client-rendered SPA (`assets/js/app.js` → `shared.js` `fetch("catalog.json")`). A plain page fetch returns the empty shell and reports **zero** plugins — always read the JSON, not the rendered HTML. |
| Arch User Repository | `https://aur.archlinux.org/packages-meta-ext-v1.json.gz` | Full extended metadata dump (~14 MB gzipped), regenerated by the AUR every few minutes. |

## Metrics and methodology

### Omarchy plugin marketplace (`catalog.json`, `.plugins[]`)

- **Total listings** — `len(plugins)`. Split into `sourceType == "community"` and
  `sourceType == "builtin"` (the built-in count also matches the `builtIn` flag).
- **Community listings unverified** — community plugins with
  `verificationStatus == "unverified"`.
- **Upstream commit ≠ listing-validated commit** — community plugins where
  `upstreamObservedCommit != listingValidatedCommit`, i.e. upstream has moved past
  the exact commit the marketplace validated at listing time. This is the core
  drift the product addresses.

Snapshot date comes from the catalog's own `generatedAt` field.

### Arch User Repository (extended metadata dump)

- **Total packages** — `len(dump)`.
- **Zero community votes** — packages with `NumVotes == 0` (no one has vouched for
  them); roughly half the AUR.
- **Changed in the last 30 days** — `LastModified` within 30 days of now, showing
  the repository churns constantly.
- **Flagged out-of-date** — packages with a truthy `OutOfDate` flag (computed but
  not currently shown on the page).

The AUR dump carries no generation timestamp in the body, so the script stamps the
snapshot with the run date. AUR context is on the page because PKGBUILDs run
arbitrary build scripts as your user and have a real malware history — the same
mutable-community-code supply-chain shape as plugins.

Numbers drift between runs (the marketplace catalog moved by one listing in the
minutes between two fetches on 2026-08-21) — that is expected for a live source and
is exactly why each figure is dated.

## Do not touch the frozen planning snapshot

The **2026-08-20, 689-entry** figures in [`docs/brainstorm.md`](brainstorm.md),
[`docs/plans/`](plans/), and [`docs/reviews/`](reviews/) are a deliberately frozen
snapshot: the product thesis and the release-corpus verification baseline as
analyzed at planning time. They are historical record and must **not** be updated
to track the live catalog. Only the landing page carries current marketplace state.
